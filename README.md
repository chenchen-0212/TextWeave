# 文织 TextWeave

> 长文自动切段，渲染到自有背景图，批量产出系列图文。

输入一段文本 + 一张背景图 → 自动分段分页 → 分别渲染 → 一次性导出多张风格统一的图片。

---

## 一、项目简介

内容创作者把一篇长文变成「系列图文」（小红书笔记、公众号配图、课程卡片、活动素材）时，通常只有两条路，而两条路都有明显缺口：

| 现有做法 | 缺口 |
|---|---|
| PS / Canva 手工拆分排版 | 一篇 3000 字文章拆成 8 张图要花 1 小时以上，改一个字就要重排全部 |
| 卡片类工具（md2card、XHS-TextCard 等） | 切分分页成熟，但**只能用纯色 / 渐变背景，无法用自己的图片做底** |
| 海报类工具（Daily News Poster 等） | 能用背景图，但**一次只出一张**，不能把长文自动切段成系列 |

TextWeave 落在两者的交集上：**A 类的分段分页引擎 + B 类的背景图叠字渲染**。

**目标用户**：内容创作者、运营/市场同学、知识博主与设计师——需要自有背景图（品牌视觉、实拍素材）作为底图，拒绝千篇一律的模板色。

**形态**：Wails v2 桌面应用（Go 后端 + WebView2 前端），打包为单个可执行文件，**纯本地运行，文本与图片不上传任何服务器**。

## 二、核心功能

### 文本处理

- **自动分段**：空行分段 → 超长段落按句末标点二次切分 → 按容量自适应分页
- **中文断行与禁则**：严格按 W3C《中文排版需求》实现行首禁则、行尾禁则、符号分离禁则（`——`、`……` 不可拆开），采用「推出」原则修正
- **孤寡行保护**：段落被分页切开时，避免一两行孤零零地留在页首/页尾（`minOrphanLines`）
- **字素级切分**：基于 `Intl.Segmenter`，正确处理 emoji、代理对、组合字符

### 目标张数约束（核心能力）

设定 `[最小张数, 最大张数]`，系统以字号为变量做**二分搜索**，自动找到满足约束的最大字号，并等比联动内边距、行高、段间距。相比线性缩放策略精度更高，能拿到全局最优解而非近似解。字号触底（24px）仍超页时明确提示，**绝不静默截断内容**。

### 背景与蒙版

- **三种填充模式**：cover / contain / stretch；cover 模式下可微调取景偏移
- **手动调参**：亮度 / 对比度 / 饱和度 / 模糊 / 暗角
- **三种蒙版形态**：圆角卡片（`card`，默认）/ 全图遮罩（`veil`）/ 上下渐变（`gradient`），支持毛玻璃
- **系列一致性**：同一张背景图在所有页使用完全相同的裁剪矩形，拼起来无跳变

### 文字与字体

- 字号、字重、颜色、行高、字间距、段间距、对齐方式、首行缩进
- **字体不内置**：枚举系统中已安装的字体（只列出覆盖汉字区的，避免选到纯拉丁字体后满屏方块），并支持上传 `.ttf` / `.otf` / `.woff2` 自定义字体，上传时校验可解码性、汉字区覆盖与嵌入授权

### 封面

- **多封面管理**：可保存多套封面，随时切换，每张封面自带标题 / 副标题 / 字号 / 字重 / 版面 / 颜色覆盖 / 独立蒙版 / **专属背景图**
- **叠加效果**：正文背景打底 → 封面图按不透明度与混合模式叠上 → 单色层 → 暗角，也可设为「独立不叠加」

### 预览与导出

- **实时预览**：参数一变立即重算全部页面，缩略图条叠加**填充率进度条**，标出过空 / 过挤的页面
- **逐张落盘**（默认）：每张图独立写入指定目录，即产即用、无需解压，内存峰值最低，中断后已导出的图仍可用
- ZIP 打包导出（可选）
- 文件名模板：支持 `{index}` / `{total}` / `{title}` / `{date}` 变量

### 模板与分享

- 参数可保存为模板（本地最多 60 个），支持导入 / 导出 `.json`
- **分享码**：把整套参数编码成 `TW1-` 前缀的短串，便于团队共享品牌视觉。分享码不含本机路径，字体路径与输出目录会被强制剥离

### 其他

- 画布尺寸完全自定义，内置手机尺寸预设（1080×1920 / 1080×2340 / 1179×2556 / 1440×3200）
- 支持拖拽导入背景图与文本文件
- 参数自动持久化，重启恢复
- Python 增强通道（预留，用于未来的图像分析 / AI 能力），**核心链路完全不依赖 Python**

## 三、快速开始

### 3.1 直接使用（推荐）

到 [Releases](https://github.com/chenchen-0212/TextWeave/releases) 下载对应平台的产物：

| 平台 | 文件 | 说明 |
|---|---|---|
| Windows x64 | `TextWeave-0.2.0-windows-amd64-portable.exe` | 便携版，双击即用，无需安装 |
| Windows x64 | `TextWeave-0.2.0-windows-amd64-setup.exe` | NSIS 安装包 |
| macOS | `TextWeave-0.2.0-macos-universal.dmg` | 拖拽安装，兼容 Apple Silicon 与 Intel |

**运行要求**：

- Windows 10 / 11 x64 —— 需要 WebView2 Runtime（Windows 11 自带；Windows 10 缺失时安装包会自动下载安装）
- macOS 10.15+ —— 未签名的 .dmg 首次打开需右键「打开」或在「系统设置 → 隐私与安全性」中手动允许

### 3.2 从源码构建

环境要求：

| 依赖 | 版本 | 备注 |
|---|---|---|
| Go | 1.21+（本项目在 1.26.5 上验证） | 需开启 cgo |
| Node.js | 18+（本项目在 22.23.2 上验证） | 用于构建前端 |
| Wails CLI | v2.15.0 | `go install github.com/wailsapp/wails/v2/cmd/wails@v2.15.0` |
| NSIS | 3.x（仅 Windows 打包安装包时需要） | `winget install -e --id NSIS.NSIS` |
| Xcode Command Line Tools | （仅 macOS） | `xcode-select --install` |

```bash
git clone https://github.com/chenchen-0212/TextWeave.git
cd TextWeave
wails doctor          # 检查环境缺什么
```

开发模式（前端热重载）：

```bash
wails dev
```

构建产物：

```powershell
# Windows：一条命令产出 exe + NSIS 安装包并整理到 dist/
powershell -ExecutionPolicy Bypass -File scripts/package-windows.ps1
```

```bash
# macOS：产出 universal .app + .dmg + .zip
bash scripts/build-macos.sh
```

> **重要**：Windows 产物只能在 Windows 上构建，macOS 产物只能在 macOS 上构建。
> Wails 通过 cgo 调用各平台原生 WebView 绑定，无法交叉编译。两个平台都要，
> 最省事的做法是推送一个 `v*` tag 走 GitHub Actions，它会同时在两个 runner 上构建。

详细的签名、公证、图标生成与常见问题见 [BUILD.md](BUILD.md)。

## 四、使用方法

```
① 导入背景图 → ② 粘贴 / 导入文本 → ③ 系统自动分段分页
                                          ↓
⑥ 全部导出   ← ⑤ 逐页微调（可选）  ← ④ 实时预览全部结果
```

1. **导入背景图**：点击「导入背景图」，或直接把图片拖进窗口。支持 PNG / JPG / WebP。
2. **导入文本**：在左侧输入框粘贴，或点击「导入文本」选择 `.txt` 文件，也可直接拖入。
3. **调参**：右侧参数面板分区折叠，依次为画布 / 背景图 / 蒙版 / 文字 / 封面 / 张数约束 / 导出。参数一改，中间预览立即重算全部页面。
4. **设置张数**（可选）：在「张数约束」里填 `[最小张数, 最大张数]`（默认 `[1, 18]`，18 对应小红书单篇图文上限），系统自动搜索最优字号。
5. **加封面**（可选）：在封面面板里填写主副标题，可保存多套封面方案随时切换，也可为封面指定专属背景图。
6. **导出**：选择输出目录与文件名模板，点击「导出全部」。默认逐张落盘，导完可直接拖进平台上传。

**关键交互原则**：所见即所得，参数一变预览立即重算，不需要点「生成」。

### 默认参数（按 1080×1920 调校）

```
画布      1080 × 1920，scale 1，PNG，quality 0.92
padding   96         maskPad 48（card 形态）
字号      48         行高 1.75     段间距比 0.9
可用宽    792 px  →  约 16 字 / 行
可用高    1632 px →  约 19 行 / 页
每页约 300 字，3000 字长文约产出 10 页
默认蒙版  card 圆角卡片 + 铺满（每页卡片位置尺寸完全一致，系列一致性最强）
```

## 五、技术架构

```
┌─────────────────────────────────────────────────────────┐
│ Wails 应用 · 打包为单个 exe / app                         │
│ ┌─────────────────────────────────────────────────────┐ │
│ │ 前端层 · WebView2 / WKWebView                        │ │
│ │  参数面板 / 实时预览 / 分页结果清单                    │ │
│ │  渲染内核：分段 → 断行 → 分页 → Canvas 合成            │ │
│ │  导出：toBlob 逐张转交 Go 落盘                        │ │
│ └─────────────────────────────────────────────────────┘ │
│                        ↕ Wails Bindings                  │
│ ┌─────────────────────────────────────────────────────┐ │
│ │ Go 后端层                                            │ │
│ │  文件与目录选择 · 图片落盘 · ZIP 打包 · 配置持久化     │ │
│ │  系统字体枚举 · 字体导入 · pyexec 子进程管理           │ │
│ └─────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────┘
```

**Text-First 架构**：排版管线（规范化 → 分段 → 断行 → 分页 → 张数约束）全部只操作纯数据结构（`Line` / `Block` / `Page`），**不接触 canvas**，只有最后一步才真正绘制。这样才能做到「参数一变整体重算」，并且张数约束的二分搜索需要反复重跑排版而不触发任何绘制。

**渲染管线七步**：文本规范化 → 段落切分 → 字素断行 + 禁则修正 → 超页段落切分 → 容量装箱分页 → 目标张数约束（二分搜索回环）→ Canvas 合成。

### 技术选型

| 层 | 选型 |
|---|---|
| 桌面框架 | Wails v2（Go + WebView2 / WKWebView） |
| 后端 | Go 1.21+ |
| 前端 | Vue 3 + TypeScript + Vite + Pinia |
| 渲染 | 原生 Canvas 2D（不引入 fabric.js / konva：画布是**只读渲染结果**，不需要对象模型） |
| 文本切分 | `Intl.Segmenter` + 自研断行器 |
| 字体 | 系统字体 + 用户上传，**不内置** |

### 目录结构

```
textweave/
├── main.go                 # Wails 入口（含 appOptions，可被单元测试覆盖）
├── app.go                  # 暴露给前端的绑定方法
├── wails.json              # Wails 项目配置
├── internal/
│   ├── picker/             # 文件 / 目录选择
│   ├── fsutil/             # 落盘、ZIP 打包、文件读取
│   ├── imageinfo/          # 背景图尺寸与格式探测
│   ├── fonts/              # 系统字体枚举 + 用户字体导入（Windows / 其他平台分文件）
│   ├── config/             # 配置持久化
│   └── pyexec/             # Python 子进程通道（预留扩展位）
├── frontend/
│   └── src/
│       ├── core/           # 纯排版逻辑，不接触 canvas
│       │   normalizer.ts  splitter.ts     graphemes.ts
│       │   FontMetrics.ts prohibition.ts  lineBreaker.ts

│       ├── render/         # 绘制层：background / masks / textPainter / CanvasRenderer / exporters
│       ├── stores/         # Pinia：参数 → 重算 → 预览；模板库

│       └── components/     # 界面：输入 / 预览 / 缩略图条 / 参数面板
├── scripts/                # 构建、打包、图标生成、逻辑验证脚本
├── build/                  # 图标源与各平台打包资源
└── .github/workflows/      # release.yml：双平台自动构建
```

## 七、已知限制

- 一张背景图对应 N 张图，暂不支持多背景图按序匹配
- 不做 AI 内容生成 / 润色 / 摘要，也不做平台一键发布
- 不做背景图智能主体检测与安全区避让（当前为手动调参）
- 不做尾页 / 页码 / 续页页眉，系列元素目前只有封面页
- 输入按纯文本处理，不做 Markdown 解析
- **不内置中文字体**：跨机器一致性依赖用户自行上传品牌字体，界面会显示当前实际生效的字体名
- 禁则采用「推出」原则修正，未实现 W3C 规定的「先挤进」（标点压缩），极端情况下行宽会有轻微参差；开启两端对齐可缓解
- Python 增强通道当前不承载核心功能，Python 缺失时相关入口置灰，核心渲染链路不受影响
